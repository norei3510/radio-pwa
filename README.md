# Radio Desk

MP3を再生するPWAです。

## 音源一覧の管理

`public/catalog.json` が音源一覧の正本です。スマホにURLを登録する必要はありません。
`scripts/update-catalog.mjs` が番組別の公式RSSから実際のMP3リンクを取得します。番号からURLを推測しません。
記事URLで重複を防ぎ、新着を追加しながら過去の音源を保持します。同じ記事のMP3リンクが訂正された場合は更新します。
2026年10月29日に3番組のタグ別RSSを最終ページまでさかのぼり、公開MP3リンクのある全記事を取り込みました。
匿名ラジオ547音源、オモコロウォッチ192音源、モンゴルナイトフィーバー346音源、計1,085件です（特別回・記事内の複数音源を含みます）。
RSSにMP3がない記事は本文も確認しています。公開MP3がない6記事は`public/archive-report.json`に公式記事URLとともに記録しています。
記事が存在しない欠番や、公開MP3がない動画・外部埋め込みのみの回は、番号からURLを推測して追加しません。
番組一覧は100件ずつ追加表示し、検索と連続再生は取得済みの全件を対象にします。
RSS取得や解析に失敗した場合は既存の一覧を書き換えず、Actionsを失敗にして知らせます。

## 自動更新

既存のGitHub Pagesワークフローに定期実行を追加しています。
日曜・月曜・木曜の日本時間12:00（UTC 03:00）に3番組を確認し、新着があれば一覧をコミットして、その実行内でPagesを再配信します。
GitHub Actionsの混雑により実際の開始時刻は遅れる場合があります。
昼の確認後にサイトへ掲載された回は次の実行で取得します。Actionsの「Run workflow」で手動取得もできます。

定期実行の開始にはこの変更をデフォルトブランチ`main`へ反映する必要があります。
Actionsの書き込み権限とGitHub PagesのActions公開を使用します。ブランチ保護でbotのpushを禁止している場合は権限の調整が必要です。
公開リポジトリでは長期間アクティビティがないとGitHub側で定期実行が停止することがあります。

## ローカルでの実行

```sh
npm ci
npm run catalog:update
npm test
npm run dev
```

過去回を再収集する場合は`npm run catalog:backfill`を実行します。RSSと本文の取得結果を`work/archive-feeds/`にキャッシュします。
最新状態で再収集する場合は、この作業用キャッシュを退避してから実行してください。通信エラーやページの繰り返しを検出した場合は途中の一覧で上書きしません。
日・月・木の定期処理は従来どおり最新RSSだけを取得し、取り込み済みの過去回は保持します。

`npm run build`で本番ビルドを確認できます。
音源自体は保存せず、公式配信元からストリーミングします。オフライン時も同梱の一覧は表示できますが、音声の再生には通信が必要です。
端末には再生設定・最後に選んだ回・各音源の再生位置を保存します。旧版のIndexedDB内の登録データは削除しませんが、新版の一覧には取り込みません。

## 途中から再開

再生位置は再生中に約5秒間隔で保存し、一時停止・シーク・画面の非表示・ページ離脱時にも同期的に保存します。
再起動後は最後に選んだ回と保存位置を表示し、再生ボタンを押すと続きから再開します。番組を切り替えても各音源の位置を個別に保持します。
聴き終えた回は先頭へ戻します。同じIDの配信URLが変わった場合は古い再生位置を使いません。
保存位置は端末内の`radio.playback-progress.v1`に保存するため、サイトデータの削除や別端末への移動では引き継がれません。
OSによる突然の強制終了では最後の定期保存時点まで戻る可能性があります。

## 修正した再生処理

再読み込み後に記憶した音源のURLを設定してから再生します。
曲を進めるたびにシャッフル順が消える処理を取り除きました。
番組を切り替えると再生を停止し、音源と表示が食い違うことを防ぎます。
日本語のタイトル検索、一覧と再生順の整合、GitHub Pages配下のPWA起動先も修正しています。
