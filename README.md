# Radio Desk

MP3を再生するPWAです。

## 音源一覧の管理

`public/catalog.json` が音源一覧の正本です。スマホにURLを登録する必要はありません。
`scripts/update-catalog.mjs` が番組別の公式RSSから実際のMP3リンクを取得します。番号からURLを推測しません。
記事URLで重複を防ぎ、新着を追加しながら過去の音源を保持します。同じ記事のMP3リンクが訂正された場合は更新します。
初期データは各番組の直近10回、計30回です。それ以前の全アーカイブは未収録です。
RSS取得や解析に失敗した場合は既存の一覧を書き換えず、Actionsを失敗にして知らせます。

## 自動更新

既存のGitHub Pagesワークフローに定期実行を追加しています。
日曜・月曜・木曜の日本時間12:00（UTC 03:00）に3番組を確認し、新着があれば一覧をコミットして、その実行内でPagesを再配信します。
GitHub Actionsの混雑により実際の開始時刻は遅れる場合があります。
昼の確認後にサイトへ掲載された回は次の実行で取得します。Actionsの「Run workflow」で手動取得もできます。

定期実行の開始にはこの変更をデフォルトブランチ`main`へ反映する必要があります。
Actionsの書き込み権限とGitHub PagesのActions公開を使用します。ブランチ保護でbotのpushを禁止している場合は権限の調整が必要です。
公開リポジトリでは長期間アクティビティがないとGitHub側で定期実行が停止することがあります。

## ローカルでの実行

```sh
npm ci
npm run catalog:update
npm test
npm run dev
```

`npm run build`で本番ビルドを確認できます。
音源自体は保存せず、公式配信元からストリーミングします。オフライン時も同梱の一覧は表示できますが、音声の再生には通信が必要です。
端末には再生設定と最後に選んだ回だけを保存します。旧版のIndexedDB内の登録データは削除しませんが、新版の一覧には取り込みません。

## 修正した再生処理

再読み込み後に記憶した音源のURLを設定してから再生します。
曲を進めるたびにシャッフル順が消える処理を取り除きました。
番組を切り替えると再生を停止し、音源と表示が食い違うことを防ぎます。
日本語のタイトル検索、一覧と再生順の整合、GitHub Pages配下のPWA起動先も修正しています。
